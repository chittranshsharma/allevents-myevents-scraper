# Discovery methodology

The default source is the reviewed public Bengaluru category hub on Mepass. With `ALLEVENTS_AUTHORIZED=true`, the first three Bangalore `/all` listing pages are added; their Event JSON-LD provides same-host detail URLs. A listing never creates a promotion claim; the detail page must contain explicit evidence. The database frontier stores normalized URL, source, depth, discovered/fetched times, priority, status, attempts, content hash and parser version. Pages are deduplicated within jobs. New event URLs outrank recently seen ones; age and explicit promotional URL keywords add a small priority bonus. The model makes no claim about private coupons.

Defaults: three seconds between requests to a host, serial fetches, 10 pages, depth 1, 20-second request timeout, 2 MB response maximum, three attempts for transient network failures, and a roughly five-minute job deadline. Server errors are recorded; access restrictions stop a host. DNS must resolve entirely to globally routable addresses. Only reviewed HTTPS hosts on port 443 are accepted, and redirects are refused. Normalization removes common marketing tracking, preserves meaningful query values and does not lowercase paths.

Content hashes plus parser versions avoid repeated extraction of unchanged pages, but fetching is still required to detect changes. Public HTML price text is considered only in explicit INR “onwards” contexts. Event subtype JSON-LD is supported; duplicate mobile/desktop nodes are deduplicated. Event links are restricted to the same reviewed source host. Sitemap sources can extract event URLs from XML; nested sitemap crawling is not implemented.

Additional sources require operator policy review. Create a JSON array and set `SOURCE_CONFIG` to its path. Each object has `url`, `platform` (`mepass` or `allevents`), `source_type` (`listing`, `sitemap`, `promotion`), `terms_url`, `permission_basis`, `official`, and optional `event_id`. External organizer sources require an existing event ID. `official=true` is a trusted operator assertion that the publisher is authoritative. The configuration grants no permission by itself; record the real authorization basis. Restart API/worker after configuration changes.

Sources are linked to events explicitly; ambiguous fuzzy matches are not accepted. Social integrations, search-provider APIs and dynamic browser extraction require separate authorized integrations. The current crawler does not implement them. Deterministic sentence-local classification avoids speculative LLM inference.
